根因分析

完整的 DNS 解析链路

为什么短名没问题

ev-edge（0 个点 < 5）第一次拼接就是 ev-edge.default.svc.cluster.local，直接命中 CoreDNS 的 kubernetes 插件，不需要转发到上游。

为什么上游不可达就会导致 FQDN 失败

正常情况下，上游 DNS 对不存在的域名会立即返回 NXDOMAIN（几毫秒），拼接尝试快速失败后就能走到最后的兜底查询。但上游不可达时，每次转发都要等超时（2-5秒），4 次拼接累计 8-20 秒延迟。nginx 启动时的 DNS 查询有自己的超时，还没等到最后一步就判定失败了。

search 域中 lan 的来源

节点的 /etc/resolv.conf 由 NetworkManager 生成，search lan 来自 DHCP 下发的域名后缀。kubelet 创建 Pod 时会把节点的 search 域追加到容器的 resolv.conf 中。
